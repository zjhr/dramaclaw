# 骨骼轴标定（Mixamo / mixamorig）

**证据边界**：MONOFORM 里唯二的手工骨骼姿势是官方作者摆的 —— `HALF_SQUAT_JOINTS`（半蹲，9 根）
与 `FULL_SQUAT_JOINTS`（全蹲，13 根），在 `frontend/vendor/monoform/src/rig.js`。
它们只能作为这些具体蹲姿关节的数值样本，不能从蹲姿差值推出所有身体部位的统一轴语义。
手臂的动作合同必须用 `stand_relaxed` / `idle` 基础下的真实 GLB 关节位移校准，不能靠猜或信 LLM 直吐角度。

## 手臂动作合同（以真实 GLB 位移为证据）

| 语义控制（站姿基础） | 真实 GLB 局部映射 | 给模型的写法 |
|---|---|---|
| `leftArm.pitch` / `leftForeArm.pitch` | 局部 Y 正向 | 负值，约 `-35~-60°`，表示前抬/伸手 |
| `rightArm.pitch` / `rightForeArm.pitch` | 局部 Y 反向 | 同样写负值，镜像由引擎处理 |
| `leftElbow.bend` | 局部 Y 反向 | 正值，约 `20~45°`，表示前弯/收拢 |
| `rightElbow.bend` | 局部 Y 正向 | 同样写正值，镜像由引擎处理 |
| `left/right Arm/ForeArm.twist` 或 `.yaw` | 局部 X | 沿骨长轴拧转，不是抬臂 |

在 `stand_relaxed` / `idle` 基础上，前抬/伸手不能只写几个 ±5° 的微小角度。
应让 Arm/ForeArm 与 Elbow 在准备、实际行动、回应/停顿和收束中出现有画面可读性的变化；
引擎负责左右镜像，模型和用户只需要使用语义控制名，不必输入局部轴。
`Shoulder` 是锁骨，只能做小幅微调，不能代替 Arm/ForeArm 抬臂；
`Shoulder.spread/roll` 的映射暂不以此文档校准。头部 `pitch` 等已有语义不因手臂校准而改变。

**校准规则**：真实 GLB 在基准姿势与目标姿势之间的局部/世界关节位移才是证据。
蹲姿表格、controls 数值、关键帧数量或读回的零偏移都不能单独证明“手已经伸到目标处”。
脚会浮空，当前也没有 IK 接触约束；这是白模粗演的限制。

## 真机实测（2026-09-20，真 MONOFORM + 真 bridge）

注入 `{"leftShoulder.spread": -85, "rightShoulder.spread": 85, "head.pitch": 20}` 后读回工程：

```
joints.mixamorigLeftShoulder  = [0, 0, -1.4835]   ← -85° 精确落位（Z 轴）
joints.mixamorigRightShoulder = [0, 0, +1.4835]   ← +85°，同轴反向 = 对称
joints.mixamorigHead          = [0.3491, 0, 0]    ← 20°（X 轴）
共 67 根骨骼；**没给的骨骼全是 [0,0,0]**
```

**这里要区分骨骼偏移与基础动画**：`cloneJointPose` 会把未写的骨骼偏移补成零；
`Viewport.jsx` 先采样 `pose` 对应的动画剪辑，再叠加这些偏移。零偏移表示保留基础动画，
不能由读回的全零字典推断人物会变成 T 形。这次 shoulder/head 读数也只是原始轴值示例，
没有在 `stand_relaxed` / `idle` 基础上证明 Shoulder 可以承担抬臂，因此不把 `spread/roll` 当作伸手合同。

## 真实 GLB 的伸手校准（2026-09-22）

用 `stand_relaxed` / `idle` 作为基准比较实际 GLB 的关节位移后，动作层采用以下语义映射：

- `leftArm.pitch` / `leftForeArm.pitch` 写入局部 Y 正向；`rightArm.pitch` / `rightForeArm.pitch`
  写入局部 Y 反向。对模型来说两侧都用负值表示前抬/伸手，左右镜像由引擎处理。
- `leftElbow.bend` 写入局部 Y 反向；`rightElbow.bend` 写入局部 Y 正向。正值表示前弯/收拢。
- `Arm` / `ForeArm` 的 `twist` / `yaw` 写入局部 X，含义是沿骨长轴拧转；它不能替代 `pitch` 抬臂。
- `Shoulder` 仍只允许小幅微调；它的映射和 `spread/roll` 不因蹲姿表格而扩展，头部 `pitch` 等旧合同保持不变。

实际动作建议：在站姿基础上，Arm.pitch 约 `-35~-60°`，Elbow.bend 约 `20~45°`，
并在准备、伸出、回应/停顿、收束拍之间体现真实幅度。仅有 `idle` 和几个微小角度不是完整伸手。

## 高级舞步的可读参数（2026-09-22）

高级舞蹈不是把关键帧数量堆高，而是让重心、腿、躯干、手臂和头部在不同时间承担不同任务。以下数值是在
标准 `xbot-animated.glb`、`stand_relaxed`、根位为零、没有已有 `joints` 的条件下，用最终
`skeletalPose.js` 采样得到的粗演范围；换成 `walk`、`crouch` 或已有姿态后要重新看画面。

| 动作层 | 语义 controls | 真实方向 / 建议范围 |
|---|---|---|
| 侧抬手臂 | `leftArm.roll` / `rightArm.roll` | 左侧正、右侧负才是向外；约 `±30~60°`，不要用锁骨大角度代替 |
| 上举双臂 | `Arm.pitch` + `ForeArm.pitch` + `Elbow.bend` | 语义 `Arm.pitch -115~-130°` 配小幅 roll、肘 `16~30°`；`-135~-145°` 才明显过头 |
| 抬膝 / 点步 | `UpLeg.pitch`、`Leg.pitch`、`Foot.pitch` | 大腿 `-35~-50°` 向前上抬，小腿约 `+25~40°`，脚尖 `-8~-18°` |
| 下沉 / 起身 | `UpLeg.pitch`、`Leg.pitch`、`hips.pitch` | 下沉大腿约 `-46°`、小腿约 `+28°`，收势显式写回 0 |
| 侧倾 / 摆胯 | `hips.roll`、`torso.roll`、`head.roll` | 髋约 `±4~10°`、躯干约 `±5~12°`，超过 `15°` 容易失真 |
| 转身 / 旋身 | `hips.yaw`、`torso.yaw`、`head.yaw` + `facing` | 用 `facing` 改变整体朝向，骨骼只做分层延迟；头部约 `±15~30°` |

动作展开器会把“向左迈、下沉、上举、转身、身体波浪、抬腿”等大白话动作拆到这些层，
并允许用 `side`、`intensity`、`at`、`facing` 和 `interpolation` 做左右不对称、重拍和停顿。
白模没有脚底 IK、手指/表情或接触求解；脚步和手部接触只能作为预演意图，不能当作精确命中。

## 演出关键帧（2026-09-22）

导演台「电影级运镜与动作编排」技能同时规划布景、人物表演与镜头。单镜头使用 `camera`，
多机位使用 `shots`；每位主要演员用 `performance` 写演出节拍，或用 `route` 写走位。
机位共享同一场戏的角色轨，但仍需手动切换，不会在一条时间线里自动剪辑。

- `performance[].t` 是秒，转换为角色轨的帧号。省略站位、朝向、姿势与骨骼轴时，
  首拍按 `mode` / `poseBase` 决定骨骼基础，此后继承上一拍；需要复位的轴显式写 `0`。
- 顶层 `mode:"compose"` 表示重新编排演出与镜头。已有演员可以继续用 `target`，
  保留对象身份和布局，但骨骼偏移默认从中性状态开始，防止上一场的拥抱、抬臂残留。
  每位主要演员在 `t:0` 明确本场的基础 `pose`；中性骨骼偏移不等于把基础动画变成 T 形。
- 顶层 `mode:"edit"` 表示在当前演出上微调，保留未声明的姿态与其他内容。
  演员的 `poseBase:"neutral"` / `"current"` 可以覆盖默认骨骼基础；
  新演出只有用户明确要求沿用手工姿态时才用 `current`。`compose` 不等于 `reset`。
- 旧格式未写 `mode` 时，仅「全员多拍表演从 0 秒明确基础 pose 开始，同时重建镜头」
  自动识别为重编。仅路线、单拍、骨骼微调或只改镜头继续采用原有增量语义。
- `current` 同时保留手动定格的动画相位、根偏移和补录的混合基姿；
  `neutral` 清除这些附加状态。没有新动作轨时，显式 `neutral` 也会删除该演员的旧轨。
- 宿主为每拍生成完整的有效骨骼偏移快照，避免引擎补零时清掉上一拍的造型。
  骨骼角度在两拍间插值，不同姿势预设与播放状态也由引擎过渡混合；
  `hold` 段保持左侧关键帧的参数（原本开启的循环仍播放），不把等待段提前插值成下一行动。
- `idle`、`walk`、`run`、`agree`、`headShake`、`wave` 按引擎的可循环表开启播放。
  `continuousMotion:false` 可显式定格，并继承到同姿势的下一拍；切换姿势恢复新动作的默认播放方式。
- `target` 编排保留角色现有位置、朝向和缩放，未声明骨骼角度是否保留由上述模式决定，
  并同步到其他镜头里同 id 的角色。其他镜头的独立对象与相机轨保留。
- 伸手、拥抱等动作主要由 `Arm`、`ForeArm` 控制；`Shoulder` 是锁骨，
  不能用过大的锁骨转角代替整条手臂运动。白模没有手指、表情或真实接触约束。

动作是否成立必须检查播放后的姿态变化，仅验证关键帧数量不足以证明演出有效。
技能先规划演员的意图、行动、对方回应与停顿，再把这些变化写入关键帧；
数据自检不能冒充已看过渲染，当前没有自动接触求解或渲染反馈验收。

## 镜头与演出的共同时间轴

- `performance[].t`、走位 `start`、`camera.start` 都是同一段的绝对秒数。
  顶层 `duration` 是整段时长；`compose` 未指定时以角色动作终点加 `0.5` 秒收尾，
  显式时长用于安排停留与余韵，避免继承旧工程后留下无目的的长尾。
- 镜头的 `start + duration` 应在全段时长内，运动时段要覆盖它要拍的行动或回应。
  执行层会将溢出镜头前移并尽量保留时长，但这种修正不能替代正确的节奏设计。
- `camera.focus` 用角色名或 id 指定被拍人物，是取景目标，不是景深移焦。
  越肩的 `subject` 是前景人物，`focus` 是被拍人物；反打交换两者。
- 同一组镜头的 `camera.axisSide` 应保持一致，可取 `positive` / `negative`。
  省略时执行层选择接近主镜头的一侧，避免正反打各自按人物朝向计算而越轴。
- 每个镜头先说明拍谁、在哪个时刻拍什么、观众要看清什么，再选择景别与运动。
  单镜或多镜按剧情需要决定；增加镜头或采样帧数不等于提升构图质量。
